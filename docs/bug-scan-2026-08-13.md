## Low

### BUG-L1 — "Last sync" time formatted in server timezone, not the user's
**File:** `src/components/mobile/mobile-dashboard.tsx:109-111`

```ts
const lastSyncLabel = p.lastSyncIso
  ? new Date(p.lastSyncIso).toLocaleTimeString("en-US", { hour: "numeric", minute: "2-digit" })
  : null;
```

**Severity:** LOW

**Description:** `MobileDashboard` has no `"use client"` directive, so it renders on
the server — the same reason the date labels in `8c525fc` had to be pinned to
`timeZone: "UTC"`. This `toLocaleTimeString` call has no `timeZone`, so it formats the
sync instant in the *server's* timezone. Unlike the date-marker fields, `lastSyncIso`
is a true wall-clock instant, so today (single-user, server ≈ your timezone) it renders
correctly. But it's the one remaining timezone-implicit format in the file the commit
just hardened, and it becomes wrong as soon as the server timezone diverges from the
viewer's — i.e. the multi-tenant / hosted-server direction the product is heading. The
displayed "Last sync 3:00 AM" would then be off by the server↔user offset.

**Suggested fix:** Format the sync time in the viewer's timezone rather than the
server's. Cleanest is to render this label client-side (a small `"use client"` child, or
`suppressHydrationWarning` with a `useEffect` that formats after mount), or thread the
user's IANA timezone through props and pass it as `timeZone`. Low priority while
single-user, but worth closing before other people's devices hit a server in a different
zone.
